커넥터·메일

지난 시간에 만든 보고서, 쓰기 껄끄러운 메일 세 통, 당첨 안내문 여섯 장 — 오늘은 이걸 전부 화면 밖으로 내보냅니다. 이번엔 진짜로 옆자리 짝꿍의 메일함까지요.

📍 오늘 배우는 것 — 껄끄러운 메일 4유형, 안내문 양산, Gmail·캘린더 커넥터, 그리고 ‘밖으로 나가는 지점엔 사람’
🎯 오늘의 가상 문제상황

지난 시간에 주간보고서를 5분으로 줄였습니다. 그런데 그 보고서는 아직 화면 안에 있습니다. 게다가 답장을 미뤄둔 껄끄러운 메일 두 통과, 보내야 하는데 미뤄둔 독촉 메일 한 통이 그대로 있고, 당첨자 6명에게 보낼 안내문도 아직 한 장도 못 썼습니다. 오늘은 밖으로 내보냅니다.

🔁 4차시와 이어집니다

오늘은 먼저 커넥터로 밖으로 나가는 길을 열고, 이미 만들어둔 4차시 보고서부터 내보냅니다. 그다음 메일을 쓰는 3단계 — ①초안 → ②교정 → ③톤 조절 — 은 지난 시간 보고서에서 쓴 것과 똑같아요. 다만 오늘은 ‘밖으로 나가기’가 붙고, 밖으로 나가는 순간부터는 되돌릴 수 없습니다.

1

커넥터로 밖으로 내보내기

📍

여기부터는 Gmail과 구글 캘린더를 차례로 연결해서, 지난 시간에 만든 보고서를 실제로 내 메일함과 일정에 꽂아넣습니다. 3차시에서 “커넥터라는 게 있다”만 봤던 걸 처음으로 직접 써보는 순간이에요.

커넥터란?

커넥터는 Claude를 내가 이미 쓰고 있는 서비스(Gmail·구글 캘린더·드라이브 등)에 이어주는 연결 통로입니다.

지금까지는 내가 파일을 첨부하고, Claude가 만든 결과를 복사해서 메일이나 캘린더에 붙여넣었죠. 커넥터를 붙이면 Claude가 대화 안에서 그 서비스의 내용을 직접 읽고, 내가 허락한 범위 안에서 메일을 보내거나 일정을 만드는 일까지 대신 합니다. 복사·붙여넣기가 사라지는 거예요.

어디서 연결하나

Claude 앱의 설정(Settings) → Connectors에서 서비스별로 하나씩 연결합니다.
구체적인 순서는 실습에서 같이 해요 — Gmail은 실습 A, 캘린더는 실습 D.

2

Gmail로 밖으로 내보내기

누구에게 보내나 — 나, 그리고 짝꿍

오늘은 받는 사람을 둘로만 제한합니다.

  • 나에게 (실습 C) — “월요일 아침에 지난주 요약이 내 메일함에 와 있게” 하는 건 실무에서 실제로 쓰는 패턴입니다. 금요일의 내가 월요일의 나에게 브리핑을 보내는 거죠.
  • 옆자리 짝꿍에게 (실습 I) — 짝을 ‘팀장님’으로 정하고 보고서를 요청 메일로 실제 발송합니다. 짝은 자기 메일함에서 받아보고 바로 피드백해 줍니다.

둘 다 잘못 나가도 수습이 되는 상대입니다. 커넥터로 처음 발송해볼 땐 이게 맞아요. 거래처·고객 주소는 오늘 쓰지 않습니다.

⚠️ 먼저 알아야 할 것 — Claude는 메일을 ‘보낼 수’ 있습니다

Gmail 커넥터를 연결하면 Claude가 직접 발송·답장·전달까지 할 수 있습니다. 대신 기본 설정에서는 매 동작 전에 승인 창이 뜹니다.

💡 승인 창이 게이트, 버튼을 누르는 손이 검수입니다

이전에 내내 배운 게 뭐였죠? “AI 결과는 검수한다”였습니다. 메일은 한 번 나가면 되돌릴 수 없어서, 시스템이 발송 직전에 “정말 보낼까요?”라고 멈춰 세웁니다. 그런데 창이 뜨는 것만으로는 아무것도 막지 못해요. 받는 사람·제목·본문을 읽고 누르는 것까지가 검수입니다.

승인 설정을 ‘항상 허용’으로 바꾸지 마세요. 편해지는 대신 게이트가 통째로 사라집니다.

그럼 “예약 발송”은? 커넥터에는 예약 기능이 없어서 Gmail 자체 기능을 씁니다. Claude가 초안을 만들어두면, 내가 Gmail에서 열어 예약 발송 버튼으로 시간을 잡습니다. 초안 작성은 AI, 예약은 Gmail, 확인은 사람 — 셋이 나눠 갖는 구조입니다.

🛠 실습 A — 커넥터 연결 (최초 1회)
⚠️ 연결 전에 두 가지
  • 개인 구글 계정으로 하세요. 연결은 그 서비스에 대한 접근 권한을 주는 것입니다. 회사 계정 연결은 사내 보안 정책을 먼저 확인하세요 (3차시에서 말씀드린 것과 같은 원칙).
  • 설정 > 개인정보에서 모델 개선(학습 허용)을 끄세요. 커넥터를 붙이면 진짜 내 메일 내용이 대화 안으로 들어옵니다. 이 설정이 켜져 있으면 그 대화가 AI 학습에 쓰일 수 있어요.
  1. Claude 앱 → 설정(Settings) → Connectors
  2. 목록에서 Gmail을 찾아 연결 → 구글 계정 로그인 → 권한 승인

막히면 여기부터 확인

  • 로그인 창이 안 뜬다 → 브라우저의 팝업 차단을 풀고 다시 누르세요.
  • 구글 계정이 여러 개다 → 로그인 화면에서 실습할 개인 계정을 골랐는지 확인하세요.
  • 권한 승인 화면에 체크박스가 여러 개 있다 → 전부 체크해야 합니다. 일부만 허용하면 메일 읽기·보내기 중 일부가 안 됩니다.
  • 연결은 됐는데 메일을 못 찾는다 → 대화창의 도구 메뉴에서 Gmail이 켜져 있는지 확인하고, 새 대화에서 다시 시켜보세요.
🛠 실습 B — 내 메일함을 자료로 쓰기 (읽기)
📍 진행 환경

오늘도 3차시에 만든 그린컵 Project 안에서 새 대화를 열고 진행합니다. 브랜드 톤·정책(배송·쿠폰)이 자동으로 반영되는 걸 메일 답장에서 바로 확인하게 됩니다.

먼저 읽기부터. 커넥터가 붙으면 내 메일함이 곧 데이터가 됩니다.

지금 연결한 건 그린컵이 아니라 진짜 내 메일함이라, 그린컵 메일은 들어 있지 않습니다. 아래 두 번째 프롬프트의 대괄호에는 내 실제 일에 쓰는 단어를 넣으세요.

"내 메일함에서 지난 2주간 받은 메일 중, 처리해야 하는데 놓친 게 있는지 찾아줘. 있으면 출처 메일 제목과 함께 정리해줘."

4차시에서 배운 검수 3층의 ②논리층 — 근거를 확인할 수 있어야 합니다. 메일함은 데이터가 방대해서 AI가 엉뚱한 걸 집어올 여지도 그만큼 큽니다.

"최근 메일에서 [내 업무 키워드]가 언급된 걸 찾아서, 반복되는 문제가 있는지 짚어줘." — 대괄호에 내 일의 단어를 (수강생 문의 · 견적 · 일정 변경 …)
✅ “없습니다”가 나와도 성공입니다

찾아보고 없으면 없다고 말하는 게 맞는 동작이에요. 없는 걸 그럴듯하게 지어내면 그게 사고입니다.

🛠 실습 C — 나에게 보내는 ‘월요일 브리핑’ 예약하기
📎 준비물 — 4차시에서 만든 주간보고서 (Word)
4차시 실습 F·G의 검수를 통과하고 4차시 실습 I에서 Word로 저장해둔 그 파일입니다. 실습 I에서도 이 파일을 씁니다.

그 보고서를 이 대화에 붙여넣거나 파일로 첨부한 뒤, 월요일 아침의 나에게 보냅니다.
바로 보내는 게 아니라 초안으로 저장하는 이유 — 커넥터엔 예약 기능이 없어서, 예약은 Gmail에서 걸어야 하기 때문입니다.

① 초안 만들기

"첨부한 주간보고서를 바탕으로, 내 주소로 보내는 메일 초안을 Gmail에 저장해줘. - 받는 사람: 내주소@example.com ← 실제 내 주소를 직접 적으세요 - 제목: [월요일 브리핑] 6월 3주차 실적 — 매출 +26% - 본문: 4차시 검수를 통과한 핵심 요약 3줄 + 이번 주 챙길 일 3가지 - 톤: 월요일 아침의 내가 30초 만에 읽고 바로 움직일 수 있게, 담백하게"

② Gmail에서 확인하고 예약

  1. Gmail을 열어 임시보관함(Drafts)에서 초안을 찾습니다
  2. 내용을 한 번 읽습니다 ← 이게 게이트입니다. 숫자가 맞나, 이상한 문장이 없나
  3. 보내기 버튼 옆 화살표 → 예약 발송 → 월요일 오전 8시 지정

③ 확인

월요일 아침, 메일함에 브리핑이 도착해 있으면 성공입니다.

💡 방금 한 게 뭔지 정리하면

데이터(엑셀) → 보고서 → 검수 → 요약 메일 → 예약 발송.
4차시에서 배운 전부가 하나로 이어져서, 실제로 내 메일함에 도착하는 결과물이 됐습니다. 지금까지는 화면 안의 텍스트였지만, 이제 처음으로 밖으로 나갔습니다.

3

캘린더에 후속 일정 꽂기

🛠 실습 D — 캘린더 연결하고 후속 일정 꽂기

① 캘린더 연결 (최초 1회)

  1. Claude 앱 → 설정(Settings) → Connectors
  2. 목록에서 Google Calendar를 찾아 연결 → 구글 계정 로그인 → 권한 승인

Gmail과 같은 개인 계정으로 로그인하세요. 막히면 실습 A의 ‘막히면 여기부터 확인’과 같은 순서로 보면 됩니다.

② 보고서의 계획을 일정으로

캘린더도 Claude가 직접 일정을 만들 수 있습니다.
4차시 보고서의 ‘이슈 및 다음 주 계획’을 실제 일정으로 바꿔봅시다.
메일은 한 통이라 한 번 읽으면 되지만, 일정은 한 번에 여러 개가 생깁니다.
하나씩 뜨는 승인만으로는 전체 그림이 안 보이니, “목록 먼저”로 내가 게이트를 하나 더 세웁니다.

"이 보고서의 '이슈 및 다음 주 계획' 항목을 내 구글 캘린더 일정으로 만들어줘. 각 항목마다 적당한 요일에 30분씩, 제목 앞에 [주간보고] 를 붙여서. 만들기 전에 어떤 일정을 언제 만들지 목록으로 먼저 보여줘."
⚠️ “만들기 전에 목록으로 먼저 보여줘”

이 한 줄을 빼지 마세요. 캘린더는 쓰기가 되기 때문에, 확인 없이 시키면 내 캘린더에 일정이 우수수 생깁니다. 되돌리려면 하나씩 지워야 하죠. 14차시에서 배울 “실행 전 확인하고 허락하기”를 여기서 미리 씁니다.

이어서(골라내기): "방금 목록에서 [확인필요]가 남아 있는 항목은 빼고, 이번 주에 내가 실제로 착수할 일만 캘린더에 만들어줘."

보고서에 팀 구성이 설정되어 있으면 “내 것만 골라내기” + “담당자 미정인 건 손대지 않기” 두 조건입니다.
실제 업무에선 여기 내 이름을 넣으면 됩니다.

💡

보고서 → 캘린더로 이어지는 이 흐름이 “보고서 쓰고 나서 따로 일정 잡는” 30분을 통째로 없애는 구간입니다. 4차시에서 만든 ‘이슈 및 다음 주 계획’이 여기서 실제 일정이 되는 거죠.

9차시 회의록에서도 똑같이 씁니다 — 회의록의 ‘할 일’ 표를 그대로 캘린더로 보내면 회의 후 30분이 사라집니다.

4

껄끄러운 메일, 30분에서 5분으로

보고서보다 더 오래 붙잡고 있는 게 있죠. 쓰기 껄끄러운 메일.
30분씩 썼다 지웠다 하는 그것들 — Claude가 특히 잘 도와주는 영역입니다.

유형마다 구조가 다르다

“정중하게 써줘”로는 부족합니다. 껄끄러운 메일은 유형별로 빠지면 안 되는 칸이 정해져 있습니다.

유형구조어려운 이유핵심 지시빠뜨리면 생기는 일
거절감사 → 명확한 거절 → 이유(간단히) → 대안·여지관계가 상하면 안 됨“정중하지만 여지 없이 명확하게”이유만 길면 변명, 대안 없으면 관계 끊김
사과인정 → 원인(짧게) → 보상·조치 → 재발방지과하면 과잉 책임, 약하면 무성의“인정할 것만 인정하고 대안 제시”보상 없이 사과만 = 무성의, 원인 길면 변명
부탁·독촉상황 확인 → 필요한 것 → 명확한 기한 → 도울 것 제안강요처럼 보이면 안 됨“상대 사정 언급 + 기한은 명확히”기한이 모호하면 또 밀림
요청배경 → 구체적 요청 → 상대 이득 → 기한·회신 방법배경만 길어지기 쉬움“내가 원하는 행동을 한 문장으로”배경만 길고 뭘 원하는지 불명확
💡

표를 가로로 읽으세요. 거절은 ‘대안’이, 사과는 ‘보상’이, 독촉은 ‘명확한 기한’이 빠지는 순간 무너집니다. AI에게 시킬 때도 이 구조를 그대로 불러주면 결과가 달라집니다.

🛠 실습 E — 거절 + 역제안 (①초안 → ②교정)
📎 준비물 — 받은 메일 3종(awkward_emails.docx) : Word

그린컵 Project 안에서 새 대화를 열고 이 파일을 첨부하세요.
Project 안에서 하면 브랜드 톤·정책(배송·쿠폰)이 자동 반영되는 것도 확인할 수 있습니다.

"첨부한 첫 번째 메일(단가 20% 인하 요구)에 답장을 써줘. 우리 내부 한도는 10%야. 5% 할인 + 무료배송 + 각인 서비스로 역제안해줘. 구조는 감사 → 명확한 거절 → 이유는 '내부 기준'까지만 → 대안. 타사 견적 언급에는 휘둘리지 말고, 우리 강점(품질·A/S)을 한 줄 넣어줘."
  • 확인 : 거절이 명확한가? (“어려울 것 같습니다”처럼 흐리면 상대가 또 물어봅니다)
  • 확인 : 거절 이유에 없는 수치를 지어내지 않았나?

거절할 때 — ‘왜’를 어디까지 말할까

방금 프롬프트에 “이유는 ‘내부 기준’까지만 → 대안”이라고 선을 그었죠. 왜 거기까지만 말했을까요?
이유를 다 말하면 협상 여지를 주고, 안 말하면 무성의해 보이기 때문입니다. 거절에서 가장 자주 막히는 지점이에요.

단가 인하 요구는 아래 표의 첫 줄, “조건이 안 맞음 → 간단히”에 해당합니다. 그래서 이유는 “내부 기준”에서 멈추고, 바로 대안(5% 할인·무료배송·각인)으로 넘어간 거예요. 상황이 다르면 공개 수준도 달라집니다.

상황이유 공개 수준예
조건이 안 맞음간단히“내부 기준상 이번 분기에는 어렵습니다”
우선순위 밀림솔직히“하반기 로드맵이 이미 확정돼 있어”
말 못 할 사정말하지 않되 명확히“검토했으나 이번엔 진행이 어렵습니다”

순서는 표로 공개 수준을 정하고 → 그걸 지시문에 상한선으로 적는 것입니다. 셋째 줄(말 못 할 사정)은 빨리 끝낸 분이 도전 과제의 ‘여지를 남기는 거절’에서 직접 써볼 수 있어요.

⚠️ 어디까지 쓸지 지정하지 않으면 AI가 없는 이유를 지어냅니다

상한선을 지시문에 적지 않으면, AI는 그럴듯한 이유를 스스로 만들어 채웁니다. 4차시에서 배운 ‘데이터에 없는 건 지어내지 않기’와 같은 원리입니다.

🛠 실습 F — 사과 + 보상 (②교정 연습)

같은 대화에서 이어서 두 번째 메일에 답장합니다.

"두 번째 메일(배송 지연 컴플레인)에 답장. 우리 잘못이 맞아(택배사 지연 + CS 응대 미흡). 구조는 인정 → 원인 짧게 → 보상(전액 환불 또는 재배송 선택 + 3,000원 쿠폰) → 재발방지 한 줄. 과한 저자세는 피하고, 변명처럼 안 들리게."
  • 확인: “죄송합니다”가 몇 번 나오나요? 3번 넘으면 오히려 무성의해 보입니다.
    “사과는 앞에 한 번만” 으로 고쳐보세요.
  • 확인: 선물 날짜가 지났다는 고객의 진짜 손해를 언급했나?
    이걸 놓치면 형식적인 답장이 됩니다.
💡

여기서 쓴 “~만 고쳐줘” 가 4차시의 ②교정입니다. 한 번에 다 고치지 말고 한 지시 = 한 개선으로 보세요.

🛠 실습 G — 독촉 + 톤 조절 (③톤 조절)

이번엔 받은 메일에 답하는 게 아니라, 내가 먼저 보내야 하는 껄끄러운 메일입니다. 같은 대화에서 이어서:

"디자인 외주 거래처에 시안 독촉 메일을 써줘. 원래 납기가 2주 전이었는데 아직 시안을 못 받았어. 다음 달 신제품 촬영 일정이 걸려 있어. 구조는 상황 확인 → 필요한 것 → 명확한 기한(이번 주 금요일 오후 6시) → 우리가 도울 것 제안. 관계는 유지하고 싶으니 탓하는 말투는 빼고, 기한만큼은 흐리지 마."
  • 확인: 기한이 날짜·시간으로 박혀 있나? “가능한 빨리”, “이번 주 중”처럼 흐리면 또 밀립니다.
  • 확인: 상대 사정을 묻는 한 줄이 있나? 없으면 강요처럼 읽힙니다.
  • 이어서 — 같은 내용, 옷만 갈아입히기
    “위 세 메일을 각각 더 격식 있게” / “절반 길이로 바꿔줘.”

메일 제목 — 열리느냐 마느냐

본문을 아무리 잘 써도 안 열리면 소용없습니다. 제목의 원칙 하나: [분류] 핵심 + 필요한 행동.

❌ 이런 제목✅ 이런 제목
“안녕하세요”“[문의] 단체주문 200개 단가 협의 요청”
“보고서입니다”“[공유] 6월 3주차 주간실적 — 매출 +26%”
“확인 부탁드립니다”“[요청] 7/5까지 회신 — 프로모션 예산안 승인”
“회의 관련”“[회의록] 6/23 운영회의 — 결정 2건·미결 3건”
🛠 실습 H — 제목 뽑기

같은 대화에서 이어서, 실습 E~G에서 쓴 세 메일의 제목을 뽑습니다.

"위 세 메일의 제목을 각각 3개씩 뽑아줘. [분류] 핵심 + 필요한 행동 형식, 30자 이내."
  • 확인: 세 제목 모두 [분류]가 붙었나?
  • 확인: 필요한 행동(회신·승인·확인)이 제목에서 보이나? 제목만 보고 “내가 뭘 해야 하지?”가 풀려야 합니다.
💡

세 개를 다 해보면 유형별 구조가 왜 다른지 몸으로 알게 됩니다. 거절은 ‘대안’이, 사과는 ‘보상’이, 독촉은 ‘명확한 기한’이 빠지면 무너집니다.
표의 마지막 유형인 요청은 실습 I에서 짝꿍에게 실제로 보내면서 해봅니다.

🛠 실습 I — 짝꿍 ‘팀장님’에게 요청 메일 보내기 (핵심 · 실제 발송)

오늘의 하이라이트입니다. 이번엔 초안이 아니라 커넥터로 실제 발송합니다. 위 4유형 표의 마지막, 요청 유형이에요.
방금 배운 제목 원칙도 여기서 씁니다.

⚠️ 시작 전에 — 짝과 주소 교환은 동의한 사람끼리만

메일 주소는 개인정보입니다. 짝과 서로 괜찮은지 먼저 묻고 교환하세요. 원치 않으면 아래 ‘혼자 하는 방법’으로 하면 됩니다. 교환한 주소는 실습이 끝나면 지워도 됩니다.

① 보내는 사람 — 무엇을 요청할지 고르기

짝을 팀장님으로 정합니다. 실습 C와 같은 4차시 주간보고서를 열고, ‘이슈 및 다음 주 계획’에서 팀장 승인이 필요한 것 하나를 고르세요.
내 보고서마다 다를 수 있습니다. 막히면 예시: “박스 모서리 보호재·완충재 보강을 다음 주부터 진행할지”

② 요청 메일 만들고 발송

구조는 위 4유형 표의 요청 줄 그대로입니다. 보고서를 대화에 첨부하고:

"첨부한 주간보고서로 팀장님께 보내는 요청 메일을 써줘. - 받는 사람: 짝꿍주소@example.com ← 짝의 실제 주소 - 요청할 것: [①에서 고른 것] - 구조: 배경(보고서 요약 3줄) → 구체적 요청 → 팀장님 입장의 이득 → 회신 기한·방법 - 회신 기한: [날짜·시간까지] ← 예: 이번 주 금요일 오후 3시 - 제목: [요청] 핵심 + 필요한 행동, 30자 이내 - 메일에 보고서 파일을 첨부하지 말고, 필요한 숫자만 본문에 넣어줘 ← 커넥터로 보낼 땐 매번 붙이는 줄 - 보내기 전에 받는 사람·제목·본문을 먼저 보여줘 ← 커넥터로 보낼 땐 매번 붙이는 줄"

대괄호 두 칸이 내가 생각해서 채우는 부분이고, 표시한 마지막 두 줄은 상황과 상관없이 매번 붙이는 습관입니다.

  • 보여준 초안을 읽습니다. 받는 사람 주소가 짝의 것이 맞나, 숫자가 4차시 검수 결과와 같나, 팀장님 입장의 이득이 들어갔나, 기한이 날짜·시간으로 박혀 있나.
  • 고칠 게 없으면 “이대로 보내줘” → 승인 창이 뜨면 한 번 더 읽고 승인합니다. 이 버튼이 오늘의 게이트예요.

③ 받는 사람(팀장님 역할) — 내 메일함에서 피드백

짝이 보낸 메일을 내 Gmail에서 열고, 팀장이 된 기분으로 세 가지만 말해주세요.

  • 제목만 보고 열고 싶었나? 무슨 메일인지, 내가 뭘 해야 하는지 제목에서 보였나
  • 스크롤 없이 첫 화면만 읽고 결정할 수 있나? 뭘 결정하라는 건지 한 문장으로 찾을 수 있나
  • 언제까지인지 바로 보이나?

두 사람이 동시에 서로에게 보내니, 각자 보내는 사람이자 받는 사람입니다. 받은 메일로 위 세 가지를 보고 피드백을 주고받으면 끝이에요.

🙋 혼자 하는 방법 (짝과 주소 교환을 원치 않을 때)

받는 사람을 내 주소로 적고 똑같이 발송합니다. 받은 편지함에서 위 세 가지를 팀장님이 됐다고 생각하고 스스로 점검하세요.

💡 실습 C와 I를 나란히 보세요

C는 초안 → 내가 Gmail에서 예약, I는 Claude가 발송 → 내가 승인입니다. 누르는 버튼은 달라도 나가기 직전에 사람이 읽고 누른다는 건 같아요.
그리고 I에서 짝이 준 피드백이 바로 받는 사람 입장의 검수입니다. 제목과 첫 화면이 안 읽히면, 아무리 정확한 보고서도 안 열립니다.

🧪 심화 — 컴플레인 주고받기 (빨리 끝낸 짝)

커넥터의 읽기 → 답장 → 발송 승인을 한 번에 경험합니다. 그린컵 Project 안에서 진행하세요.

  1. A(고객 역할) : awkward_emails.docx의 두 번째 메일(배송 지연 컴플레인) 내용을 짝에게 보냅니다.
    “이 컴플레인 내용을 고객 입장에서 짝꿍주소@example.com 으로 보내줘. 제목은 [문의] 주문 상품 배송 지연.”
  2. B(그린컵 담당자) : 내 메일함에서 그 메일을 찾아 같은 스레드에 답장합니다.
    “내 메일함에서 ‘배송 지연’ 메일을 찾아서, 우리 잘못이 맞아(택배사 지연 + CS 응대 미흡). (인정 → 원인 짧게 → 보상 → 재발방지)로 쓰고, 보내기 전에 먼저 보여줘.”
    확인: 프롬프트에 정책 얘기를 안 했는데, 보상이 Project에 올려둔 배송·교환·환불 정책 기준으로 나왔나요? 정책대로 나왔다면 Project 지식이 일한 겁니다. 정책에 없는 보상을 약속했다면 보내기 전에 고치세요 — 고객에게 나가는 순간 회사가 지켜야 할 약속이 됩니다.
  3. B가 초안을 읽고 승인 → A가 받은 답장을 보고 고객으로서 화가 풀렸는지 말해주기.

안내문 양산 템플릿 1개 × 데이터 N행

4차시에서 템플릿으로 보고서 한 장을 찍었습니다. 템플릿의 진짜 위력은 여러 명에게 보내는 문서에서 나옵니다.

당첨 안내문 30명, 거래처 공지 20곳 — 내용은 거의 같고 이름·상품·날짜만 다르죠.

공식은 단순합니다: 템플릿 1개 × 데이터 N행 = 완성 문서 N개. (전통적으로 ‘메일 머지’라 불리던 작업 — 이제 데이터 주고 말로 시키면 끝입니다.)

  1. 템플릿 — 케이스마다 바뀌는 부분을 {{변수}}로 표시
  2. 데이터 — 변수 값들을 표(엑셀)로. 한 행 = 한 문서
  3. 양산 — 둘을 함께 주고 “각 행을 넣어서 사람마다 만들어줘”
⚠️ 양산의 검수 포인트

① 변수 매칭 — 엉뚱한 사람에게 엉뚱한 상품이 가는 사고가 제일 흔함
② 케이스 누락 — 데이터 행 수와 결과 수가 일치하나
③ 외부로 나가는 문서이니 발송 전 사람이 최종 확인.

🛠 실습 J — 안내문 양산
📎 준비물 — 안내문 템플릿(notice_template.docx) : Word · {{변수}} 포함
📎 당첨자 케이스 데이터(winner_cases.xlsx) : Excel · 6명

새 대화를 열고 두 파일을 함께 첨부하고:

💡 템플릿인데 왜 첨부?

원칙대로면 안 바뀌는 템플릿은 Project행입니다. 오늘은 연습용 한 회차라 첨부로 씁니다
— 내 업무에서 반복해 쓸 안내문이라면 Project에 올려두세요.

"이 안내문 템플릿의 변수를, 당첨자 데이터 각 행에 맞춰 채워서 6명 각각의 완성된 안내문을 만들어줘. 사람마다 구분되게."

→ 개인화 안내문 6개가 한 번에

이어서(검수): "방금 만든 안내문에서 각 사람의 당첨상품·마감일이 데이터와 정확히 일치하는지 표로 대조해줘."

→ 변수 매칭 사고 거르기

SMS용 짧은 버전·VIP 톤 변형은 도전 과제로 옮겨뒀습니다.

🔍 관찰 포인트

결과가 정확히 6개인가요? 데이터 행이 6줄인데 5개만 나왔다면 그게 케이스 누락입니다. 사람 수가 많아질수록 이 사고가 조용히 늘어납니다 — 그래서 매번 행 수와 결과 수를 세는 습관이 필요합니다.

도전 과제 빨리 끝낸 사람용

그린컵으로 한 걸음 더 — 수업 자료 그대로, 5분 안팎

  • 여지를 남기는 거절 (받은 메일 3종 중 세 번째): 실습 E와 같은 대화에서 이어서
    "세 번째 메일(콜라보 제안)에 거절 답장. 조건이 우리에게 불리해서 이번엔 어렵지만, 업계가 좁아 나중에 다시 만날 수 있으니 관계는 확실히 남기고 싶어. 거절 사유는 구체적으로 쓰지 말고 '이번 분기 리소스' 선에서."
    확인: 거절인데 다시 연락하고 싶어지는 톤인가? 실습 E의 ‘여지 없는 거절’과 나란히 놓고 비교해 보세요.
  • 안내문 변형 (실습 J 이어서):
    "같은 내용을 문자(SMS)용 2~3줄 짧은 버전으로도 6명분." "VIP 고객(이수진)에게는 더 정중한 톤으로."
    확인: SMS 버전도 6개인가, 이수진 님 것만 톤이 바뀌었나.

내 업무로 가져가기 — 내 실제 자료로

  • 내 진짜 업무로: 그린컵 말고 내 실제 반복 업무 하나를 골라 같은 흐름을 만들어보기 — 자료 → 요약 → 나에게 예약 메일 → 후속 일정. 이게 오늘 배운 걸 내 것으로 만드는 가장 빠른 길입니다.
  • 내 껄끄러운 메일 하나: 지금 답장을 미뤄둔 실제 메일 한 통을 골라, 오늘의 유형별 구조로 초안을 만들어보기. (보낼지 말지는 나중에 결정해도 됩니다)
  • 내 안내문 템플릿: 내가 반복해서 보내는 안내문·공지문 하나를 {{변수}} 형태로 바꿔 저장해두기.
⚠

흔한 실수 6가지

  1. 승인 창을 읽지 않고 누름 — 창이 떠도 안 읽고 누르면 게이트가 없는 것과 같다. 특히 받는 사람 주소부터 본다.
  2. 캘린더에 바로 쓰게 함 — “목록 먼저” 한 줄을 빼면 일정이 우수수 생기고 하나씩 지워야 한다.
  3. 거절이 흐릿함 — “정중하게”만 시키면 “어려울 것 같습니다”가 나온다. 구조를 지정하라: “감사 → 명확한 거절 → 대안”.
  4. 거절 이유를 지어냄 — 상한선을 안 주면 AI가 그럴듯한 수치를 만든다.
  5. 사과가 과잉 — “죄송합니다”가 세 번 넘으면 오히려 무성의하게 읽힌다. 보상이 빠진 사과는 더 무성의하다.
  6. 양산 결과 수를 안 셈 — 6행인데 5개가 나왔는지 확인 안 하면 한 명이 통째로 빠진다.

자주 묻는 질문 FAQ

Q.커넥터로 보낸 메일을 취소할 수 있나요?
A.

되돌릴 수 없다고 생각하세요. 그래서 승인 창에서 받는 사람 주소부터 봅니다. 확신이 없으면 먼저 초안으로 저장해서 Gmail에서 직접 확인하고 보내면 됩니다.

Q.승인 창이 매번 뜨는 게 번거로운데, ‘항상 허용’으로 바꿔도 되나요?
A.

바꾸지 마세요. 편해지는 대신 게이트가 통째로 사라집니다. 특히 커넥터에 익숙하지 않은 지금은 승인 창이 가장 확실한 안전장치예요.

Q.설정에 ‘모델 개선(학습 허용)’ 메뉴가 안 보여요.
A.

회사에서 쓰는 Team·Enterprise 요금제는 기본적으로 대화가 학습에 쓰이지 않아서 이 항목이 없을 수 있습니다. 개인 요금제라면 설정의 개인정보 메뉴에서 확인하세요.

Q.회사 메일 계정을 연결해서 써도 되나요?
A.

사내 보안 정책을 먼저 확인하세요. 연결은 그 메일함 전체에 대한 접근 권한을 주는 것입니다. 회사 요금제를 쓴다면 관리자가 연결 가능 여부를 정해두었을 수 있습니다.

Q.그린컵 Project 밖에서 메일을 써도 되나요?
A.

메일 쓰기 자체는 됩니다. 다만 Project에 올려둔 브랜드 톤·배송·교환·환불 정책이 반영되지 않아요. 보상·정책이 걸린 답장은 꼭 Project 안에서 쓰세요.

오늘 정리

  • [커넥터] Gmail은 발송·답장·전달까지, 캘린더는 일정 생성까지 된다. 대신 Gmail은 기본 설정에서 동작마다 승인 창이 뜬다 — 승인 창이 게이트, 버튼을 누르는 게 사람의 검수.
  • [커넥터] 예약 발송은 커넥터에 없다 → 초안 → Gmail에서 예약. 첨부파일은 확실하지 않으니 보낼 내용은 본문에.
  • [커넥터] 캘린더처럼 한 번에 여러 개가 바뀌는 작업은 승인 창만으론 전체가 안 보인다 → “목록 먼저”로 내가 게이트를 하나 더 세운다.
  • [메일] 유형마다 구조가 다르다 — 거절엔 대안, 사과엔 보상, 독촉엔 명확한 기한이 빠지면 무너진다.
  • [메일] 거절 사유는 어디까지 쓸지 지정하지 않으면 AI가 없는 이유를 지어낸다.
  • [메일] 제목은 [분류] 핵심 + 필요한 행동. 본문을 잘 써도 안 열리면 소용없다.
  • [양산] 템플릿 1개 × 데이터 N행 = 문서 N개. 단, ①변수 매칭 ②케이스 누락 ③발송 전 사람 확인 세 가지는 필수.
  • 자동화 설계의 규칙: 되돌릴 수 없거나 밖으로 나가는 지점에는 사람이 선다. (20차시 철칙의 예고편)

자가진단 퀴즈

1. Gmail 커넥터로 메일을 보낼 수 있다면, 사람의 검수는 어디서 일어나나?

정답 보기

발송 전 승인 창에서. 받는 사람·제목·본문을 읽고 승인 버튼을 누르는 것이 검수다. 그래서 승인 설정을 ‘항상 허용’으로 바꾸면 안 된다. (예약 발송은 커넥터에 없으니 초안 → Gmail에서 예약)

2. 캘린더 지시에 반드시 붙일 한 줄은?

정답 보기

“만들기 전에 목록으로 먼저 보여줘.” 일정은 한 번에 여러 개 생겨서, 하나씩 뜨는 승인 창만으로는 전체가 안 보이기 때문.

3. 거절 메일에서 절대 빠지면 안 되는 칸은?

정답 보기

대안(또는 여지). 사과는 보상, 독촉은 명확한 기한.

4. 거절 이유를 어디까지 쓸지 지시에 넣지 않으면?

정답 보기

AI가 없는 이유를 지어낸다. 상한선을 지정할 것.

5. 안내문 6명분을 만들었을 때 가장 먼저 셀 것은?

정답 보기

결과 수가 데이터 행 수와 같은가(케이스 누락), 그다음 변수 매칭.
